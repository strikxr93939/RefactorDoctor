# Refactor Doctor

Локальный помощник для безопасной модернизации устаревшего Python‑кода. Он
добавляет аннотации типов и docstrings, заменяет типовые `os.path`‑конструкции
на `pathlib`, переводит `print` на `logging`, форматирует результат Black и
проверяет его через AST, компиляцию и Pylint.

## Возможности

- принимает `.py`‑файл или код из stdin;
- сохраняет исходные имена и сигнатуры функций;
- создаёт Google‑ или NumPy‑docstrings;
- выполняет безопасные AST‑преобразования без Ollama;
- при доступной `qwen2.5-coder:7b` улучшает типы и читаемость;
- отклоняет ответ LLM с синтаксической ошибкой или изменённым интерфейсом;
- пишет отдельный `*.refactored.py`, а `--in-place` сначала создаёт `.bak`;
- возвращает JSON с изменениями, рисками и оценками Pylint.

AST‑проверка не доказывает полное сохранение поведения. Перед заменой production‑
кода обязательно запустите тесты проекта и проведите code review.

## Установка

```powershell
cd agent_04_legacy_refactor
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
Copy-Item .env.example .env
ollama pull qwen2.5-coder:7b
```

## Использование

Создать соседний файл `legacy.refactored.py`:

```powershell
refactor-doctor .\legacy.py
```

Указать результат и использовать только AST‑режим:

```powershell
refactor-doctor .\legacy.py --output .\modern.py --no-llm
```

Прочитать фрагмент из stdin:

```powershell
Get-Content .\legacy.py -Raw | refactor-doctor - --output .\modern.py
```

Для NumPy‑docstrings добавьте `--docstring-style numpy`. Режим `--in-place`
доступен только для файла и будет отменён, если соответствующий `.bak` уже есть.

Интерфейс запускается командой `refactor-doctor-web` на
`http://127.0.0.1:8004`. Код можно загрузить как `.py` или вставить прямо в
редактор. Кнопка «Вставить пример» позволяет проверить бота без подготовки
файла. По умолчанию используется быстрый детерминированный режим; глубокий
анализ через Ollama включается отдельно и при недоступности модели безопасно
возвращается к локальным правилам.

После обработки интерфейс показывает исходный и итоговый код рядом, список
изменений, сохранность интерфейсов, оценки Pylint и их разницу. Результат можно
скопировать или скачать как отдельный `.refactored.py`.

## Что проверяется

1. Исходный и итоговый код разбираются `ast.parse`.
2. Итог компилируется через `compile`, но пользовательский код не запускается.
3. Сравниваются имена и сигнатуры всех функций.
4. Black форматирует результат.
5. Pylint рассчитывает оценку до и после; значение ниже 9/10 попадает в warnings.
